1. What a Semantic Model Is

A semantic model is a business description of a database table. It tells the system which column uniquely identifies a row, which fields can be used for grouping and filtering, and which fields should be aggregated as measures.

After models are committed, agents can answer business questions with list_metrics, list_dimensions_for_metric, and query_metric instead of writing fragile aggregation SQL by hand.

2. Quick Start

Step 1: Create a model YAML file

# models/orders.yaml
---
semantic_model:
  name: orders
  db_table: dw.orders
  defaults:
    agg_time_dimension: order_date

  entities:
    - name: order
      type: primary
      expr: order_id
    - name: user
      type: foreign
      expr: user_id

  dimensions:
    - name: order_date
      type: time
      type_params:
        time_granularity: day
      expr: order_date
    - name: channel
      type: categorical
      expr: channel
    - name: status
      type: categorical
      expr: status

  measures:
    - name: total_amount
      agg: sum
      expr: amount
      description: Total order amount
    - name: order_count
      agg: count_distinct
      expr: order_id
      description: Order count

Step 2: Add the project time configuration

# models/project.yaml
---
time_config:
  calendar:
    - table: dw.dim_date
      column: date_id
      grain: day

Step 3: Validate and commit

  1. Open the Web UI and stage the YAML files, or push them with the CLI.
  2. Run Validate to check YAML syntax, file structure, table existence, column names, entity definitions, and duplicate names.
  3. Run Commit to publish the validated staged version.
  4. Use list_metrics to discover metrics and query_metric to query them.

3. Model Structure

FieldTypeRequiredDescription
namestringYesGlobally unique model name. Use lowercase letters, digits, and underscores.
db_tablestringYesPhysical Doris table in database.table form, for example dw.orders.
defaultsobjectYesDefault settings. Currently must include agg_time_dimension.
entitieslistYesEntity definitions. At least one primary entity is required.
dimensionslistYesFields available for grouping and filtering.
measureslistRecommendedAggregation definitions. Measures create queryable metrics by default.
descriptionstringNoHuman-readable model description.
labelstringNoDisplay label.
primary_entitystringConditionalRequired when no entity has type: primary.
Names must start with a lowercase letter, contain only lowercase letters, digits, and underscores, avoid consecutive underscores, and contain at least two characters.

4. Entities

Entities describe uniqueness and relationships between tables.

TypeMeaningTypical Use
primaryUnique for each row and covers the whole table.ID column for the table. Each model should have exactly one primary entity.
foreignReference to another model. Values may repeat or be null.user_id, product_id, customer_id.
uniqueUnique identifier that may not cover every row.Email address, external reference number.
naturalReal-world unique identifier.SKU, barcode, employee number.
entities:
  - name: order
    type: primary
    expr: order_id
  - name: user
    type: foreign
    expr: user_id

5. Dimensions

Dimensions define how data can be grouped and filtered. Use time for date/time fields and categorical for discrete buckets.

FieldDescription
nameDimension name.
typetime or categorical.
type_params.time_granularityRequired for time dimensions. Supported grains include day, week, month, quarter, year, hour, and minute.
exprColumn name or SQL expression. Defaults to name when omitted.
is_partitionMarks a partition column. Default is false.

6. Measures

Measures define aggregations. Each measure creates a same-named metric unless create_metric: false is set.

AggregationMeaningExamples
sumSum values.Total amount, total quantity.
countCount rows or non-null values.Event count.
count_distinctCount unique values.Unique users, unique devices.
averageAverage value.Average order value, average duration.
minMinimum value.Lowest price, earliest timestamp.
maxMaximum value.Highest price, latest timestamp.
medianMedian value.Median order amount.
percentilePercentile value.P95 amount, P99 latency.
sum_booleanSum boolean values.Conversion count, qualified count.

7. Advanced Metrics

Advanced metrics are defined with top-level metric: YAML documents. They combine existing measures or metrics.

TypePurposeTypical Use
ratioNumerator divided by denominator.Conversion rate, margin, share.
derivedExpression over one or more existing metrics.Month-over-month growth, weighted calculations.
cumulativeAccumulates a metric over a time window.Last 7 days sales, month-to-date registrations.
conversionAnalyzes conversion between two events.Visit-to-order or signup-to-purchase conversion.
# models/order_conversion_rate.yaml
---
metric:
  name: order_conversion_rate
  type: ratio
  description: Order conversion rate
  type_params:
    numerator: order_count
    denominator: visit_count

8. Common Patterns

GoalPattern
Hide helper measuresSet create_metric: false.
Group by monthUse a time dimension with time_granularity: month, or pass the supported grain through query_metric.
Join dimensions across tablesDeclare primary and foreign entities consistently, then use list_dimensions_for_metric to discover valid joins.
Filter aggregated resultsUse having in query_metric, for example total_amount > 1000.

9. Troubleshooting

ErrorLikely CauseFix
Staging must be validated before commitCommit was called before successful validation.Run Validate and fix reported errors before committing.
Table not founddb_table points to a missing Doris table.Check database/table names and permissions.
Column not foundexpr references a missing column.Use describe_table or Doris metadata to verify the schema.
Duplicate metric or model nameTwo YAML files export the same object name.Rename one object or delete the duplicate file.
Semantic layer not initializedThe workspace has no committed valid model, or bootstrap failed.Open the Web UI, validate staging, and inspect the error message.

10. Managing Models

Model changes follow a strict staging workflow:

stage YAML changes -> Validate -> Commit -> automatic reload -> healthy workspace

Only the Doris admin user can create, edit, delete, validate, commit, discard, or deploy example models. Authenticated non-admin users can inspect models and query data with their own Doris permissions.

1. Connect an AI Agent

Ask your administrator for the MCP Server URL, your Doris username/password, and the workspace name that contains semantic models. The default workspace for the bundled sample is example.

Claude Desktop / Claude Code

claude mcp add --transport http doris http://<host>:3000/mcp \
  --header "Authorization: Bearer <user>:<password>"

Cursor / VS Code

{
  "mcpServers": {
    "doris": {
      "type": "http",
      "url": "http://<host>:3000/mcp",
      "headers": {
        "Authorization": "Bearer <user>:<password>"
      }
    }
  }
}

Verify the connection by asking the agent to check service health. The agent should call check_service_health and report "doris": "connected".

2. Available MCP Tools

ToolPurpose
get_query_guideMandatory first step. Returns workflow rules, semantic layer routing, raw SQL fallback rules, and query syntax.
check_service_healthReturns Doris connectivity and each workspace status: healthy, no_models, or not_ready.
list_metricsLists available metrics in a workspace.
list_dimensions_for_metricLists valid group_by dimensions for one metric.
query_metricPrimary tool for counts, sums, rates, averages, rankings, and trends. Compiles and executes semantic SQL.
reload_semantic_layerManually reloads a workspace after model changes.
list_databasesLists Doris databases for raw SQL fallback or metadata discovery.
list_tablesLists tables in a database.
describe_tableReturns physical table schema at names, summary, or full detail.
execute_queryRaw SQL fallback. Only SELECT, SHOW, DESCRIBE, and EXPLAIN are allowed.

3. Recommended Agent Workflow

get_query_guide()
check_service_health()
if a healthy workspace exists:
  list_metrics(workspace)
  list_dimensions_for_metric(workspace, metric_name)
  query_metric(workspace, metrics, group_by, where, order_by, limit, having)
else:
  list_databases()
  list_tables(database)
  describe_table(database, table)
  execute_query(sql)
If the semantic layer is healthy and a matching metric exists, use query_metric. Do not bypass it with raw SQL.

4. CLI Client

The doris-mcp-client command line client calls MCP tools and manages semantic model files through the same Bearer authentication.

export DORIS_MCP_SERVER=http://<host>:3000
export DORIS_MCP_TOKEN=<user>:<password>

# List tools and inspect arguments
./mcp-client.sh tool list
./mcp-client.sh tool describe query_metric

# Call tools
./mcp-client.sh tool call check_service_health
./mcp-client.sh tool call list_metrics --json '{"workspace":"example"}'
./mcp-client.sh tool call query_metric --json '{"workspace":"example","metrics":["total_amount"],"group_by":["channel"]}'

# Manage semantic model files
./mcp-client.sh semantic list -w example
./mcp-client.sh semantic push ./models -w example
./mcp-client.sh semantic pull -o ./backup -w example
./mcp-client.sh semantic reload -w example
./mcp-client.sh semantic status

5. Query Examples

Explore metadata

User: List all databases.
AI: calls list_databases

User: List tables in the dw database.
AI: calls list_tables

User: Show the schema for dw.orders.
AI: calls describe_table

Query semantic metrics

User: What is the total order amount by channel for the last 7 days?
AI:
  1. calls get_query_guide
  2. calls check_service_health
  3. calls list_metrics and matches total_amount
  4. calls list_dimensions_for_metric and verifies channel
  5. calls query_metric with metrics=["total_amount"], group_by=["channel"]

Raw SQL fallback

User: Show the top 10 rows from dw.orders.
AI: calls execute_query with a read-only SELECT statement
